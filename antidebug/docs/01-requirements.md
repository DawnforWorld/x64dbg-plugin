## 1. 背景

`D:\project\vmp` 工作区里有一个用 VMProtect 加壳的样例程序（开了反调试选项），
普通附加 x64dbg 会被它发现并拒绝正常调试。那里已经写过一个能用的内核驱动
（`vmp\vmp`，约 2500 行）验证了思路，但它有几个硬伤：

1. **没有开关**：驱动一加载就对全系统所有用户进程生效，想关只能卸载重启。
2. **没有界面**：所有状态只能靠内核调试输出（DbgPrintEx）看。
3. **加一个钩子要改 5 处**：函数类型定义、全局变量、地址解析、派发分支、处理函数。
4. **构建和加载不规范**：没有 CMake，加载方式未定。

本项目的需求就是把这些问题解决掉，做成一个规范的、可长期维护的 x64dbg 插件。

## 2. 目标（必须做到）

| 编号 | 需求 | 验收方式 |
|---|---|---|
| R1 | 完整移植 vmp 的 10 个系统调用钩子，处理语义保持一致（常量、返回值、改写字段都一样） | 对照 docs/08 的映射表逐项代码走查；docs/07 样本验证 |
| R2 | CMake 统一管理，一条命令构建全部产物 | `cmake --preset win-x64-release` 出 .sys/.exe/.dp64；x86 预设出 .dp32 |
| R3 | 用 vtdbg 的手法加载驱动（iqvw64e 手动映射），驱动本身不需要签名 | `antictl smoke` 完整走通（由用户在管理员终端执行） |
| R4 | hook 引擎用 InfinityHookPro 的实现，支持 Win7~Win11 24H2 | docs/04 兼容矩阵；19045 实测 |
| R5 | **按进程生效**：只有加入"隐藏名单"的进程（默认空）会被改写结果 | `antictl hide <pid>` 后生效，未加入的进程行为不变 |
| R6 | **11 项技术可独立开关**（运行时，不用重启） | UI / `antictl tech <mask>` 切换后立即生效 |
| R7 | **插件有控制界面**：能启动/停止驱动、隐藏/取消隐藏当前调试进程、开关技术、状态显示 | x64dbg 菜单打开控制面板操作 |
| R8 | 调试会话自动化：开始调试自动隐藏被调试进程，结束调试自动取消（可在 UI 关掉） | 对话框勾选后，附加目标不再触发反调试 |
| R9 | 32 位调试支持：在 x64 系统上调 32 位目标程序（WOW64，32 位程序跑在 64 位系统上的兼容层）时，相关技术同样生效 | x32dbg + vmp 32 位样例验证 |

## 3. 非目标（明确不做）

| 编号 | 内容 | 不做的理由 |
|---|---|---|
| N1 | 用户态隐藏（注入、改 PEB） | 对强保护无效；内核方案已覆盖 |
| N2 | 时间类反调试对抗（rdtsc 等） | vmp 基线没有；引擎需要改时钟路径，再做对抗互相打架，风险大收益小 |
| N3 | 时间类反调试对抗的另一半：PEB/NtGlobalFlag/堆标志 等用户态字段改写 | 同 N1，属于用户态范畴 |
| N4 | 驱动数字签名、正常 SCM 服务加载 | 手动映射路线已定；签名加载是 docs/09 同级的备选话题 |
| N5 | 32 位 Windows 内核支持 | 引擎（`__readgsqword` 读 64 位 GS 段）和 iqvw64e 手法都是 x64 专属 |
| N6 | 反检测/隐身对抗（隐藏我们自己的驱动、对抗 EDR） | 研究工具定位，不做攻防军备 |
| N7 | 多调试器同时控制一台机器的仲裁 | 研究场景单机单人，最后写入者生效即可 |

## 4. 使用场景（验收剧本）

**场景 A（主场景）**：分析一个 VMProtect 加壳、开了反调试的 32 位程序。
x64dbg（x32dbg）打开它 → 插件自动隐藏该 PID → 程序的 `NtQueryInformationProcess`、
`NtSetInformationThread`、`NtClose` 等检查全部返回"干净"结果 → 正常单步调试。

**场景 B（冒烟）**：不打开 x64dbg，管理员终端跑 `antictl smoke`：
加载驱动 → 查询版本/状态 → 停止 → 报告每步结果。

**场景 C（管理）**：打开控制面板，逐项关掉某项技术，观察目标程序对应的
检测是否恢复"发现调试器"——用于确认每项技术的实际效果。

## 5. 约束

- 内核驱动受"手动映射"约束：禁 CRT、禁异常（SEH 的 `__try/__except` 允许）、
  禁 RTTI、禁栈保护、全局变量零初始化（详见 CONTRIBUTING.md）。
- 用户态代码可用标准 C++17（静态链接 CRT，避免依赖）。
- iqvw64e.sys 的字节任何情况不进 git 仓库（法律与安全原因，见 docs/06）。
