## 1. 用途限定（先说清楚）

本项目是**安全研究/逆向分析工具**，用于在自己的机器上分析自己有权分析的程序
（例如测试 VMProtect 保护强度、学习反调试原理）。它会让"反调试检测"失效，
这层能力与加壳厂商的意图相悖——请遵守当地法律法规和软件授权协议，
不要用于侵犯他人软件权益或任何违法用途。

## 2. 运行前置条件（缺一不可）

加载驱动（`antictl load` / 插件"加载并启动"）需要：

| 条件 | 怎么检查/设置 | 为什么需要 |
|---|---|---|
| 管理员权限 | 管理员终端运行 | NtLoadDriver 需要 SeLoadDriverPrivilege |
| 内核隔离（内存完整性 / HVCI / VBS）关闭 | Windows 安全中心 → 设备安全性 → 内核隔离 → 关闭"内存完整性"，重启 | 开着时未签名代码进不了内核 |
| 微软"易受攻击驱动阻止列表"关闭 | 同上界面（Win11 22H2+），或注册表 `HKLM\SYSTEM\CurrentControlSet\Control\CI\Config` 下 `VulnerableDriverBlocklistEnable`=0（DWORD），重启 | iqvw64e.sys 在阻止列表里；开着时 NtLoadDriver 返回 `STATUS_IMAGE_CERT_REVOKED`，antictl 有专门提示 |
| 杀软/EDR 放行 | 白名单 | iqvw64e + 手动映射是典型恶意行为特征，研究机上建议关掉或加白 |

**不**需要：测试签名模式（`bcdedit /set testsigning on` 不用开——iqvw64e 本身
是 Intel 签名的正常驱动）、关闭 Secure Boot（除非上面第 2 条要求）。

普通操作（`antictl status/version`、构建、只读查询）不需要以上任何条件。

## 3. 对系统做了什么（知情清单）

加载窗口内，加载器/驱动会：

1. 把 iqvw64e.sys 落盘到 %TEMP%（随机名）→ 注册表服务项 → NtLoadDriver →
   用完即卸载并**先覆写随机数据再删文件**；
2. 顺手清掉自己加载留下的内核痕迹（PiDDB 缓存表、内核哈希桶、已卸载驱动
   记录）——这是 vtdbg/kdmapper 的既有行为，目的是不给后续加载找麻烦；
3. 在内核内存放一个小驱动镜像 + 一个设备对象（`\Device\Antidbg`，仅管理员可开）；
4. 修改 ETW CKCL 日志会话的时钟指针（停止时还原，docs/04 §7）；
5. 把 16 字节会话密钥写进 `HKLM\SOFTWARE\Antidbg`（停止时删除）。

**停止（unload）后**：以上 3/4/5 全部还原/删除；但**驱动镜像本身留在内核内存里
直到重启**（手动映射的固有代价，docs/02 §4.3）。

## 4. 已知风险与残余风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 蓝屏 | 驱动 bug 会直接蓝屏（内核代码没有例外）；引擎对未知系统版本的兜底是"干净失败"，但不能保证零风险 | 在虚拟机/快照里首次验证新系统版本；docs/07 的顺序执行 |
| 时钟漂移 | 引擎占用取时钟路径，睡眠唤醒后系统时间可能漂（参考工程的已知问题）；停止时的 QpcBias 修正是按已知的坑处理的 | 长时间不用就停止；发现时间不对可手动同步 |
| 密钥注册表可读 | `HKLM\SOFTWARE\Antidbg` 普通用户可读。若被调试进程恰好以管理员运行，理论上能读到密钥并碰控制设备 | 研究场景可接受；要更严可把密钥用 DPAPI 加密存（未来工作） |
| 被目标程序发现驱动存在 | 目标若枚举设备/驱动可看到 `\Device\Antidbg`。vmp/TitanHide 一系工具都如此 | N6 非目标（不做隐身对抗）；介意就换名字重编 |
| iqvw64e 本身的漏洞面 | 加载窗口内系统带着一个已知漏洞驱动（用完即卸） | 窗口只有几百毫秒；用完卸载是默认行为 |
| 全局 hook 的波及面 | 引擎回调发生在**每次系统调用**，一旦处理函数有 bug 影响全系统 | 热路径代码保持最小；隐藏名单为空时派发直接放行（零改写） |

## 5. 故障排查速查

| 症状 | 大概率原因 |
|---|---|
| `NtLoadDriver 返回 0xC0000603`（CERT_REVOKED） | 驱动阻止列表没关（§2） |
| `intel_driver::Load` 后打开 `\\.\Nal` 失败 | 杀软拦截 / 前一实例残留（重启可清） |
| 邮箱 FailStep=6（引擎初始化失败） | 当前系统版本特征码没扫到，看内核日志里的具体步骤（docs/04 §8） |
| 加载成功但目标照样发现调试器 | PID 没进隐藏名单（`antictl status` 看名单）；或该检测走的是未覆盖的技术（docs/03 §6 之外，如时间类检测——N2 非目标） |
| 停止后再加载失败 | 手动镜像卸不掉：同一次开机里"停止"后不能再"加载"（会话已存在），重启后才行 |

| 组件 | 来源 | 许可 | 我们的处理 |
|---|---|---|---|
| InfinityHook 引擎（ETW 时钟钩子） | `antidebug/InfinityHookPro`（FiYHer 原作，zhutingxf 传档） | MIT | 移植进 `driver/src/engine/`，保留版权头；修停止还原缺陷 |
| 10 个钩子处理函数 | `D:\project\vmp\vmp` | 未带许可文件（私有研究代码） | 按用户授权移植；语义保留，结构重写 |
| kdmapper（iqvw64e 装载/映射） | TheCruZ/kdmapper 一系（经 vtdbg 的拷贝） | MIT | 移植进 `loader/src/kdm/`，保留版权头；池标签从 'BwtE' 改为 'Adbg' |
| 加载窗口协议（邮箱/入口形态） | `D:\project\vtdbg`（GPL-3.0） | GPL-3.0 | **只借鉴协议思想，代码重写**（我们发 MIT，不能直接抄 GPL 实现代码） |
| 插件 SDK（pluginsdk 头 + .lib） | x64dbg 项目（经 TitanHide 拷贝） | GPL-3.0（x64dbg 项目许可） | 头文件与 .lib 作为**外部接口**链接使用，不修改、不分发其源码；法律上链接 GPL 库的分发注意事项见下 |
| iqvw64e.sys 字节 | Intel 网卡驱动 | Intel 专有 | 任何情况不入库；用户自行提供（docs/05 §3） |

**关于 pluginsdk 的许可注意**：x64dbg 的 SDK 按 GPL 流转。本仓库自用/内部研究
没有问题；若将来要公开分发本插件，需重新评估与 GPL 的兼容方式（动态链接 +
不分发 SDK + 源码开放是常见做法）。当前定位：内部研究工具，不分发。

## 7. 数据隐私

本工具不收集、不上传任何数据。所有状态只在本机内存和注册表里。
